BUILD TECH BUDDY CHATBOT - Complete Project from Scratch

Build a local-first technical support chatbot with text/voice interfaces, RAG over SOP documents, and device management tools.

CORE FEATURES:
1. Text Chat (HTML/CSS/JS) - Browser chat with streaming SSE responses
2. Voice Chat (Realtime API) - Wake word "Hey Buddy", function calling, menu-driven
3. RAG System - Chunk & embed SOPs (.txt/.docx), cosine similarity search
4. MCP Tools - register_ont, register_router, swap_ont, device_status, push_config
5. Conversational Flows - Multi-step guided ONT registration and swap
6. SQLite Databases - chatbot.db (chat history) + devices.db (device management)
7. Test Analytics - Generate mock data and retrospective reports
8. End Chat Button - Reset session state (fixes topic-switching errors)

TECH STACK:
- Backend: Python 3.9+, FastAPI, SQLAlchemy, SQLite, OpenAI SDK
- Frontend: Native HTML/CSS/JS (no frameworks), SSE streaming, WebRTC
- Tools: Anaconda, python-docx, numpy
- APIs: GPT-4o-mini (LLM), text-embedding-3-small (embeddings), gpt-4o-realtime-preview (voice)

KEY IMPLEMENTATION DETAILS:

1. VOICE CHAT SESSION CONFIG (CRITICAL):
   - Wait for session.created event BEFORE sending session.update
   - Must include modalities: ['text', 'audio'] for transcription
   - Use "ON THE FIRST USER TURN" pattern in instructions
   - Wake word "Hey Buddy" detected but not processed as turn
   - silence_duration_ms: 1200 (allows full serial number entry)
   - Tools in session config for function calling

2. CONVERSATIONAL FLOWS:
   - Store state in sessions.meta_data as JSON
   - ONT Registration: awaiting_serial → check exists → awaiting_location → awaiting_speed
   - ONT Swap: awaiting_old_serial → awaiting_new_serial → awaiting_speed → awaiting_reason
   - Cancel handling: Check message.strip().lower() == "cancel" BEFORE uppercase conversion

3. MCP TOOLS:
   - Accept BOTH serial_number and device_id parameters (voice vs text compatibility)
   - Check for duplicates before registration
   - ONT swap: mark old as "replaced", register new with inherited config
   - Store in devices.db with separate ont/router tables

4. END CHAT FEATURE:
   - Red button next to Send in text chat
   - Calls POST /api/sessions/{session_id}/end
   - clear_session_state() to reset conversational flows
   - Generate new UUID, clear UI, show success message
   - Prevents errors when switching device management → SOP questions

5. RAG SYSTEM:
   - Chunk: 500 chars, 100 overlap
   - Embeddings stored as BLOB: np.array(...).tobytes()
   - Retrieve: np.frombuffer(chunk.embedding, dtype=np.float32)
   - Top-K cosine similarity search
   - Auto-ingest on startup from sops/ directory

6. DATABASE SCHEMAS:
   chatbot.db: sessions(id, created_at, updated_at, meta_data), messages(id, session_id, role, content, created_at), tool_logs(id, session_id, tool_name, arguments, result, timestamp), documents(id, filename, content, ingested_at), chunks(id, document_id, chunk_index, text, embedding)
   
   devices.db: ont(id, serial_number UNIQUE, location, status, vlan, speed, port, ont_type, fiber_type, wireless_backup, technician, notes, registered_at, updated_at), router(id, serial_number UNIQUE, location, status, ip_address, subnet_mask, gateway, dns_primary, dns_secondary, wifi_ssid, wifi_password, notes, registered_at, updated_at)

CRITICAL FIXES TO IMPLEMENT:
- Voice transcription: modalities: ['text', 'audio'] + session.update timing
- Cancel command: Check lowercase before uppercase conversion
- Parameter flexibility: Accept serial_number OR device_id
- Embedding storage: Convert to bytes for SQLite BLOB
- Voice interruption: 1200ms silence threshold
- State carryover: End Chat button clears session state

TESTING CHECKLIST:
✓ Text: Send message → streaming response with citations
✓ Voice: "Hey Buddy" → menu → "register ONT" → conversational flow
✓ Tools: Register ONT/router, swap ONT with speed change, check status
✓ Cancel: Type "cancel" mid-flow → state cleared
✓ End Chat: Click button → new session, no state carryover
✓ RAG: Ask "How to install OMEGA ONT" → retrieves relevant chunks
✓ Databases: chatbot.db and devices.db created with correct schemas
